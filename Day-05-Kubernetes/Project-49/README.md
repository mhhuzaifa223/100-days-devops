# Project 49 — Kubernetes Monitoring Stack

## Objective
Deploy a Kubernetes monitoring stack to collect cluster and workload metrics, visualize system health, and support alerting.

## Technologies
- Kubernetes (Kind)
- Helm
- Prometheus
- Grafana
- Alertmanager
- Node Exporter
- kube-state-metrics
- kubectl

## How It Works
- Node Exporter exposes host-level metrics.
- kube-state-metrics exposes Kubernetes object and workload state.
- Prometheus collects metrics from configured targets.
- Grafana provides dashboards and metric visualization.
- Alertmanager handles alerts generated by Prometheus.

The stack was deployed using the `prometheus-community/kube-prometheus-stack` Helm chart.

## Application
- Prometheus: http://localhost:9090
- Grafana: http://localhost:3000

These local URLs work while their respective `kubectl port-forward` commands are running.

## How to Run
1. Ensure the Kind cluster `devops-lab` is running.
2. Deploy the stack:

       helm install project-49 prometheus-community/kube-prometheus-stack \
         --namespace monitoring --create-namespace \
         --set grafana.service.type=ClusterIP \
         --set prometheus.service.type=ClusterIP \
         --set alertmanager.service.type=ClusterIP \
         --set prometheus.prometheusSpec.retention=1d \
         --timeout 10m

3. Check the pods:

       kubectl get pods -n monitoring

4. Access Prometheus:

       kubectl port-forward -n monitoring svc/project-49-kube-prometheus-prometheus 9090:9090

5. In another terminal, access Grafana:

       kubectl port-forward -n monitoring svc/project-49-grafana 3000:80

## Testing / Failure Scenario
The Grafana and Prometheus pods initially remained in `ContainerCreating` and `PodInitializing` because their main container images were taking too long to download. The images were pulled directly with Docker, loaded into the Kind cluster, and the affected pods were recreated. Both pods subsequently reached their ready state.

## Troubleshooting
- Check pod status: `kubectl get pods -n monitoring`
- Inspect pod events: `kubectl describe pod <pod-name> -n monitoring`
- Check recent namespace events: `kubectl get events -n monitoring --sort-by=.lastTimestamp`
- For slow image downloads, pull the image with Docker and load it into Kind:

      docker pull <image>
      kind load docker-image <image> --name devops-lab

- Keep each port-forward process running while accessing its local URL.
