# Project 12 — Team Collaboration Workflows

## Objective

Learn how developers collaborate on the same Git repository using branches, commits, remote repositories, and Pull Requests.

## Technologies

- Git
- GitHub
- Linux

## What I Practiced

- Working with a shared Git repository
- Creating feature branches
- Making changes in isolated branches
- Creating commits
- Pushing branches to GitHub
- Pulling changes from a remote repository
- Creating Pull Requests
- Reviewing changes before merging
- Merging changes into the main branch

## Git Collaboration Workflow

Main Branch → Feature Branch → Make Changes → Commit → Push → Pull Request → Code Review → Merge

## Commands Used

- git branch
- git switch
- git status
- git add
- git commit
- git push
- git pull
- git merge

## Testing

A separate feature branch was used to isolate changes from the main branch.

Changes were committed locally and pushed to GitHub. The branch was then used for Pull Request-based collaboration before merging the changes into the main branch.

## Key Concepts Learned

- Git repository
- Remote repository
- Main branch
- Feature branch
- Branch isolation
- Commit
- Push
- Pull
- Pull Request
- Code review
- Merge
- Team collaboration

## Why This Matters

Feature branches allow developers to work independently without directly changing the main branch.

Pull Requests provide a controlled process for reviewing, testing, and merging changes before they become part of the main codebase.
