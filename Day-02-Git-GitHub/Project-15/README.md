# Project 15 — Release Management Using Git Tags

## Objective

Learn how Git tags are used to mark specific commits as software releases and provide stable version references.

## Technologies

- Git
- GitHub
- Linux

## What I Practiced

- Creating commits for release versions
- Creating Git tags
- Creating annotated tags
- Listing existing tags
- Inspecting tagged commits
- Pushing tags to GitHub
- Using tags to identify release versions

## Release Workflow

Code Changes → Commit → Create Tag → Push Tag → Release Reference

## Commands Used

- git tag
- git tag -a
- git tag -l
- git show
- git push
- git push --tags
- git log

## Testing

A release point was created by tagging a specific Git commit with a version identifier.

The tag was inspected to verify that it pointed to the intended commit and was then pushed to the remote GitHub repository.

## Key Concepts Learned

- Git tags
- Annotated tags
- Release versions
- Version identifiers
- Tagged commits
- Local tags
- Remote tags
- Release management

## Why This Matters

Git tags provide stable references to important points in a project's history.

They are commonly used to identify production releases such as v1.0.0, v1.1.0, and v2.0.0.
